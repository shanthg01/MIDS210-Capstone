**2026-06-23 to 2026-06-25 — Player Projection Phase 2a, reconciled against [Issue #37](https://github.com/shanthg01/MIDS210-Capstone/issues/37), real-data validated, beats Phase 0 on offense:** cross-season Kalman state-space layer on top of Phase 1, plus 7 reconciled gaps (A-G: shared-prior block correlation, observation-layer context adjustment, real rate projections, Phase 0 shrinkage-prior integration, archetype evaluation metadata, real `player_projections` write, validation-vs-Phase-0). Real-data result, rolling-origin held-out comparison: **Phase 2a beats Phase 0 on offense every fold (~5-6% RMSE reduction), ties on defense.** It first wrote real same-season diagnostic rows under `model_version="player-projection-phase2a-v1"` (33,540 rows), separate from Phase 0 by model version. Two follow-on additions landed after the Issue #37 reconciliation: an 11th skill (`foul_discipline`, Phase 1/2-only — `hoopr_player_game_logs.fouls` was the one real unused offensive/defensive metric) and an offense/defense feature-set split for the value-translation model (kept despite a real, measured ~30%-relative defense-accuracy cost, for interpretability). A teammate's review of the issue surfaced and got 3 more real fixes: a test-fixture `expires_at` staleness bug in `scripts/seed_test_data.py` (masked locally by coincidental real-pipeline writes), missing `seasons` in two cache filenames, and a `season_rank`-only join-key risk (fixed by threading the real `season` value through instead). Two real performance bottlenecks (found via profiling, not guessing) cut full real-data runs from hours to ~10 minutes along the way, which is what made this session's real-data iterate-fix-rerun cycle practical at all. This entry is historical; the later `player-proj-phase2a-fcast-v1` next-season forecast entry below is now the production API default. Full record in `../models/player_projection_state_space_plan.md` §22 and [Issue #37](https://github.com/shanthg01/MIDS210-Capstone/issues/37)'s comments.
